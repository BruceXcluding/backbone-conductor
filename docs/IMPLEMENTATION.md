## 模块关系

```text
CLI / HTTP / MCP
       │
       ▼
Conductor service ── optional DSHReviewer → DeepSeekHarness SDK
       ├── protocol models
       ├── conflict rules
       └── GitStore → state.json + generated views + audit commits
```

Git 是唯一权威存储；进程重启直接恢复快照，当前不需要 SQLite 缓存。

## 对原草案的修正

1. 个人项目首版不依赖假定的十人团队和 18 周排期。
2. Pydantic 模型提供输入验证和 JSON Schema，保留原领域对象与生命周期。
3. DSH 通过 `deepseek_harness.DeepSeekHarness` 接入；草案的 Python `dsh.Agent/Plugin` 不是核实过的 API。
4. MCP 客户端插件不充当服务端；服务端使用官方 Python MCP SDK。
5. 默认模式仍把 `.backbone/` 记录在代码仓库当前分支；新仓库可显式创建独立 `backbone` orphan 分支的隐藏 worktree。现有内联快照可在无活跃任务、代码工作树干净时显式迁移：元数据分支以迁移前代码 HEAD 为父提交，当前树仅含 `.backbone/`，代码分支另作删除快照的提交；旧审计历史仍在分支祖先中。Conductor 分别使用元数据 worktree 和代码工作树，任务分支、制品检查与代码合并始终依照代码工作树。`refresh` 只接受同名远端分支并快进；`reconcile` 要求管理员提供已审查的两侧 SHA 和理由，竞争对象还必须逐一提供本地、远端或完整合并值的决议；不合并代码。
6. 磁盘 `version` 为 null，`parent_version` 保存上次版本。读取时从最近 `.backbone/` commit 补全当前版本，避免保存提交自身 SHA 的循环依赖。
7. 无模型时明确要求人工语义审查；模型建议也不授予合并权限。
8. MCP `--member` 是本地工具约束，不防范拥有相同文件权限的用户。HTTP 默认仅供可信本机管理员使用；可选的 bearer 认证把成员绑定到自己的任务与 author，审查者有独立的只读与审批/仲裁权限；已认证 principal/角色写入元数据提交 trailer。该 trailer 是服务端鉴权结果的记录，不是 Git 签名证明。启用 Git 提交签名后可验证协调端密钥，但仍不能把该密钥绑定到某个 HTTP principal；远程部署还需可信证书、外部 Git 权限控制与真实多人演练。
9. 分派后的决策变化使产物检查中的 context 关卡失败，要求显式刷新任务。提交通过后才变化的决策需要在完成记录中留下人工复核理由。
